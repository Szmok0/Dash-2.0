# PROMPT STARTOWY DLA CODEX / CLAUDE CODE

Budujesz lokalną aplikację Windows „Client Workbench”.

Przeczytaj w całości PRODUCT.md, UI.md, DATABASE.md, WORKFLOW.md, BUILD.md i schema.sql.

Zasady:
1. Nie dodawaj funkcji spoza dokumentacji.
2. Nie zmieniaj architektury bez zgody.
3. Bez chmury, sieci i AI.
4. Realizuj wyłącznie Sprint 0.
5. Sprint 0 to klikalny shell UI z danymi testowymi, bez SQLite.
6. Zachowaj wysoką gęstość informacji, ciemny motyw, stały sidebar i layout z UI.md.
7. Dashboard ma zawierać tabelę zadań oraz prawe moduły „Bez kontaktu >30 dni” i „Wymagają uwagi”, search ID/nazwisko, licznik aktywnych i dzisiejsze spotkania.
8. Karta klienta to osobny ekran z lewą kolumną danych i równymi modułami.
9. Dane testowe: różne priorytety/statusy, zakończone zadanie przekreślone, długa notatka min. 20 wierszy, klient ze zdjęciem i bez zdjęcia.
10. Po zakończeniu uruchom aplikację, wykonaj screenshot Dashboardu i Karty Klienta w 1920×1080 i 1366×768, wypisz pliki oraz sposób uruchomienia. Nie przechodź do Sprintu 1 bez akceptacji.
